## Story

**As a** solo developer,
**I want** to deploy the historical backfill and RSS ingestion functions to production with real data sources,
**so that** the production system automatically ingests books from the actual Goodreads RSS feed and the historical CSV is permanently loaded into the production database.

1. Production environment variables and secrets are configured in Supabase (GOODREADS_RSS_FEED_URL_READ, GEMINI_API_KEY, etc.)
2. All Edge Functions (telegram-webhook, seed-lookup-data, csv-backfill, enrich-metadata, rss-ingestion) are deployed to production using `supabase functions deploy`
3. Lookup tables in production database are seeded with data from YAML files (classifications.yaml, recommendation-sources.yaml)
4. Historical books from goodreads_read_history.csv are imported into production books table (one-time operation)
5. RSS ingestion pg_cron job is active and running daily in production to fetch new books from actual Goodreads RSS feed
6. Production deployment includes verification tests to confirm all functions are accessible and responding correctly
7. Production deployment is documented with step-by-step instructions including rollback procedures
8. Post-deployment validation confirms data is correctly loaded and RSS ingestion is functioning

### Rollback Strategy

**If Deployment Fails:**

1. **Identify Last Working Commit**:
   ```bash
   # View recent commits and deployments
   git log --oneline -10

   # Check git tags for releases (if tagged)
   git tag -l

   # Identify the last known good commit (typically the commit before current HEAD)
   git log --oneline --all --graph --decorate
   ```

2. **Function Errors - Rollback to Previous Version**:
   ```bash
   # Checkout previous working commit
   git checkout <previous-commit-hash>

   # Redeploy all functions from that commit
   supabase functions deploy

   # Verify rollback succeeded
   supabase functions list
   curl -X POST https://<project-ref>.supabase.co/functions/v1/<function-name> \
     -H "Authorization: Bearer <anon-key>"

   # Return to main branch when confirmed
   git checkout main
   ```

3. **View Function Deployment History**:
   ```bash
   # List all function versions (if available via Supabase CLI)
   supabase functions list

   # Check Supabase Dashboard → Edge Functions → Deployments tab for history
   # Note: Supabase does not currently provide CLI-based deployment history
   # Use git history as source of truth for function versions
   ```

4. **Data Corruption - Restore Database Backup**:
   ```bash
   # Use Supabase Dashboard → Database → Backups
   # Restore to point-in-time before deployment

   # Verify restoration
   SELECT COUNT(*) FROM books;
   SELECT COUNT(*) FROM genres;

   # Re-run deployment if needed after restoration
   ```

5. **Cron Job Issues - Disable Temporarily**:
   ```sql
   -- Disable the cron job
   SELECT cron.unschedule('daily-rss-ingestion');

   -- Verify it's removed
   SELECT * FROM cron.job WHERE jobname = 'daily-rss-ingestion';

   -- Re-enable when fixed (run migration again)
   ```

6. **Secret Issues - Update and Redeploy**:
   ```bash
   # Update individual secret
   supabase secrets set KEY=new_value

   # Or update from .env file
   supabase secrets set --env-file .env

   # Verify secrets updated
   supabase secrets list

   # Redeploy affected functions
   supabase functions deploy <function-name>
   ```

**When to Rollback vs Fix-Forward:**

- **Rollback**: Critical production errors, data corruption, complete function failures
- **Fix-Forward**: Minor bugs, logging issues, non-breaking errors that can be patched quickly
- **Rule of Thumb**: If fix will take >15 minutes, rollback and fix in development
