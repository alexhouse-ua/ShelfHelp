# Story 1.5.1: Hardcover API Client

## Status

Draft

## Story

**As a** ShelfHelp backend system,
**I want** a robust, rate-limited GraphQL client for the Hardcover API,
**so that** I can reliably fetch books, activities, reading sessions, and lists data without exceeding rate limits or causing API failures.

## Acceptance Criteria

1. Client module created at `supabase/functions/_shared/hardcover-client.ts` with typed GraphQL query builders
2. Rate limiting implemented: 60 requests/minute queue with automatic backoff on 429 responses
3. Caching strategy implemented with TTL-based invalidation (books: 24h, activities: 5min, lists: 1h, user: 1h)
4. Error handling covers all HTTP status codes (200, 401, 403, 404, 429, 500) with appropriate retry logic
5. Exponential backoff on rate limit errors (2s, 4s, 8s for 3 attempts)
6. GraphQL query builders implemented for: Books, Activities, Editions, Authors, Lists, Users (me)
7. Authentication header format validated: `authorization: [TOKEN]` (NOT "Bearer TOKEN")
8. All client methods covered by unit tests with >80% coverage
9. Client respects API constraints: 30s query timeout, 3-level depth max, disabled operators (_like, _ilike)
10. Comprehensive logging for all API calls, errors, and rate limit events

### API Specifications

**Endpoint:** `https://api.hardcover.app/v1/graphql`
**Method:** POST (GraphQL over HTTP)
**Authentication:** Bearer token in `authorization` header (NOT "Bearer TOKEN" format)

- Header format: `authorization: [TOKEN_VALUE]` (critical: no "Bearer" prefix!)
- Environment variable: `HARDCOVER_API_TOKEN`
- Token expiry: January 1st annually (auto-reset)

**Rate Limits:**

- 60 requests/minute
- 86,400 requests/day (60/min × 1440 min)
- Query timeout: 30s max
- Query depth: 3 levels max
- Disabled operators: `_like`, `_ilike`

**HTTP Status Codes:**

- 200: Success
- 401: Invalid/expired token → Throw `HARDCOVER_TOKEN_EXPIRED`
- 403: Access denied → Throw `HARDCOVER_API_ERROR:403`
- 404: Not found → Throw `HARDCOVER_API_ERROR:404`
- 429: Rate limited → Exponential backoff (2s, 4s, 8s, then throw `HARDCOVER_RATE_LIMITED`)
- 500: Server error → Throw `HARDCOVER_API_ERROR:500`

**Data Access Scope:**

- ✅ Own user data (via `me` query)
- ✅ Public data (books, authors)
- ✅ Followed users' data
- ❌ Other private users

### Caching Strategy

Implement in-memory TTL-based cache with different expiration times based on data volatility:

```typescript
interface CacheConfig {
  books: { ttl: 24 * 60 * 60 * 1000 },      // 24h - metadata stable
  activities: { ttl: 5 * 60 * 1000 },        // 5min - progress updates
  lists: { ttl: 60 * 60 * 1000 },            // 1h - lists change slowly
  user: { ttl: 60 * 60 * 1000 }              // 1h - profile stable
}
```

**Cache Key Generation:** Combine query + variables to create stable cache keys. Recommended approach: JSON stringify the query + variables together, or use a stable hash function. Ensure identical queries with identical variables always produce the same cache key.

Example:
```typescript
// Simple approach: JSON stringify (sufficient for this use case)
const cacheKey = `${query}:${JSON.stringify(variables)}`;

// More robust: Use a hash function for consistent key length
import { createHash } from "std/crypto/mod.ts";
const combined = `${query}:${JSON.stringify(variables)}`;
const hash = createHash("sha256").update(combined).toString();
const cacheKey = `hc:${hash}`; // hc = hardcover
```

**Cache Operations:**

- Check cache before API call
- Store successful responses in cache with TTL
- Invalidate on-demand via `invalidate(key)` or `clear(type)`
- Log cache hits/misses: `operation=cache_check`, `cacheHit`, `cacheType`

### Rate Limit Handling

**Implementation:**

```typescript
// Exponential backoff on 429: 2s, 4s, 8s (3 attempts)
async function callHardcoverAPI<T>(query: string, variables: any, retries = 3): Promise<T> {
  for (let attempt = 1; attempt <= retries; attempt++) {
    const response = await fetch("https://api.hardcover.app/v1/graphql", {
      method: "POST",
      headers: {
        "authorization": process.env.HARDCOVER_API_TOKEN,
        "content-type": "application/json",
      },
      body: JSON.stringify({ query, variables }),
    });

    if (response.status === 429) {
      const waitTime = Math.pow(2, attempt) * 1000; // 2s, 4s, 8s
      await sleep(waitTime);
      continue;
    }

    if (response.status === 401) {
      throw new Error("HARDCOVER_TOKEN_EXPIRED");
    }

    if (!response.ok) {
      throw new Error(`API error: ${response.status}`);
    }

    return (await response.json()).data;
  }
}
```

```graphql
query GetUserActivities($userId: String!, $since: timestamptz!) {
  activities(
    where: {
      user_id: {_eq: $userId},
      event: {_eq: "UserBookActivity"},
      created_at: {_gte: $since}
    },
    order_by: {created_at: asc}
  ) {
    id, book_id, event, created_at, data
  }
}
```
