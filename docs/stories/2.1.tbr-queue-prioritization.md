# Story 2.1: TBR Queue Prioritization

## Status

Ready for Review

## Story

**As a** prolific reader with a large "To Be Read" queue,
**I want** the system to automatically score and prioritize my TBR queue based on multiple factors,
**so that** I can quickly identify which book I should read next without experiencing decision fatigue.

## Acceptance Criteria

1. System calculates a priority score for each book with status 'to_read' based on defined scoring factors
2. Queue position is automatically assigned based on calculated priority scores (higher score = lower queue_position number)
3. Priority scores are recalculated when relevant book data changes or when triggered by scheduled jobs
4. The scoring algorithm considers multiple weighted factors including:
   - Reading speed projections (based on page count and historical reading pace)
   - Upcoming deadlines (e.g., book club dates, library hold expirations)
   - External hype signals (bestseller lists, trending status, new release timing)
   - User preference alignment (based on learned preferences from past reflections)

   **Note on Preference Alignment:** For Story 2.1, preference alignment will use a simplified approach (ai_rating field only). The full preference model from Story 2.4 (reflection-based learning) will be integrated in a future story or as an enhancement.

   **Implementation Note:** Acceptance criteria do NOT require LLM orchestration or LangChain usage. Implement as deterministic business logic with configurable weights and formulas.

5. System exposes a mechanism for the Telegram bot to query and display the prioritized queue to the user

#### 3. Priority Scoring Algorithm Specification ✅

**Scoring Formula:**

```
Priority Score = (W1 × Reading Speed) + (W2 × Deadline Urgency) + (W3 × Hype Signal) + (W4 × Preference Alignment)
```

**Weight Constants** (sum = 1.0):

- **W1 (Reading Speed)**: 0.10
- **W2 (Deadline Urgency)**: 0.40 (highest weight - deadlines drive urgency)
- **W3 (Hype Signal)**: 0.25
- **W4 (Preference Alignment)**: 0.25

**Factor Calculations:**

**W1 - Reading Speed Factor:**

- **Formula**: `Score = 1 - (page_count / (avg_pace × 30 days))`
- **Data source**: `books.page_count` + `user_preferences.preference_value` where `preference_key='reading_pace'`
- **Reading pace calculation**:
  - Calculate from `user_date_added` → `user_date_finished` timestamps in books table
  - Update `avg_pages_per_day` in user_preferences after each completed book
  - Store as JSONB: `{"avg_pages_per_day": 50, "last_calculated": "2025-10-03", "sample_size": 10}`
- **Interpretation**: Higher score = faster to read (shorter books prioritized when time-constrained)

**W2 - Deadline Urgency Factor:**

- **Formula**: `Score = max(0, 1 - (days_until_deadline / 30))`
- **Data source**: `deadlines` table (new)
  - Query for active deadlines: `SELECT deadline_date FROM deadlines WHERE book_id=$1 AND status='active' ORDER BY deadline_date ASC LIMIT 1`
  - Types: book_club, library_hold, reading_challenge, personal
- **Interpretation**: Higher score = more urgent (books due soon prioritized)
- **No deadline fallback**: Score = 0 (neutral)

**W3 - Hype Signal Factor:**

- **Formula**: `If hype_flag=true → 1.0; else → 0.0`
- **Data source**: `books.hype_flag` (BOOLEAN)
- **Interpretation**: Binary signal for trending/popular books

**W4 - Preference Alignment Factor:**

- **Formula**:
  1. Find READ books with matching `genre` OR `author`
  2. Calculate `avg_ai_rating` from those books
  3. `Score = avg_ai_rating / 10`
  4. Fallback (no similar READ books): `Score = 0.5` (neutral)
- **Data source**: `books.ai_rating` (from similar READ books)
- **Example**:
  - TBR Book: "New Agatha Christie Mystery"
  - Similar READ books: `ai_ratings = [8, 9, 7, 8]` → avg = 8.0
  - Score = 8.0 / 10 = 0.80
- **Note**:
  - `ai_rating` comes from post-read reflection (Story 2.3+)
  - May differ from `user_rating` (RSS feed) - this is intentional
  - User's manual ratings are mood-based; AI provides consistent assessment

**AI Integration Decision:**

- **Selected**: Full AI scoring with Gemini Pro
- **Model**: `gemini-2.5-pro-preview-03-25` (complex reasoning)
- **Prompt template**: "Calculate priority score for book with attributes: {attributes}"
- **Hybrid approach**: Use deterministic business logic where applicable, AI for nuanced scoring

#### 4. Database Schema Changes ✅

**Migration created**: `supabase/migrations/20251003000000_add_story_2_1_schema.sql`

**New table: `deadlines`**

```sql
- id (UUID, PK)
- book_id (UUID, FK → books.id)
- deadline_date (TIMESTAMP WITH TIME ZONE)
- deadline_type (TEXT: book_club, library_hold, reading_challenge, personal)
- title (TEXT, optional: "Mystery Book Club", "Main Library")
- description (TEXT, optional)
- status (TEXT: active, completed, cancelled)
- completed_at (TIMESTAMP)
- created_at, updated_at (TIMESTAMP)
```

**Books table additions:**

```sql
ALTER TABLE books ADD COLUMN:
- priority_score (DECIMAL 5,4, range 0-1)
- last_score_calculated (TIMESTAMP WITH TIME ZONE)
```

**User preferences (existing table):**

- Store reading pace as: `preference_key='reading_pace'`
- `preference_value` (JSONB): `{"avg_pages_per_day": 50, "last_calculated": "...", "sample_size": 10}`

**Indexes added:**

- `idx_deadlines_book_id`, `idx_deadlines_date_active`, `idx_deadlines_status`
- `idx_books_priority_score` (for queue queries)

**Design rationale:**

- Separate `deadlines` table chosen over `book_events` for semantic clarity:
  - `book_events` = past actions (audit trail)
  - `deadlines` = future constraints (commitments)
- Supports multiple active deadlines per book
- Clean query patterns for priority scoring
- Status tracking (active/completed/cancelled)
