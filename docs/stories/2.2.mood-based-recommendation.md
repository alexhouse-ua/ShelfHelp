# Story 2.2: Mood-Based Recommendation

## Status

Done

## Story

[Epic Reference: docs/epics/epic-2-ai-intelligence-user-interaction.md - Story 2.2]

**As a** reader looking for my next book,
**I want** to receive personalized book recommendations based on my current mood or reading preferences,
**so that** I can discover books from my TBR queue that match what I'm in the mood to read right now.

## Acceptance Criteria

1. System provides a `/recommend` bot command that accepts natural language mood/preference input
2. User can describe their desired reading experience using free-form text (e.g., "something light and funny", "dark mystery", "uplifting romance")
3. System uses Gemini Flash to extract semantic intent from the user's mood description
4. System performs hybrid search (vector similarity + keyword matching) against books with status='to_read' in the database
5. System returns top 3 book recommendations ranked by relevance to the user's mood query
6. Each recommendation displays: title, author, AI summary (if available), and relevance score
7. Response includes inline keyboard buttons for user actions: "Add to top of queue", "Tell me more", "Show more results"
8. If no suitable matches found (relevance threshold not met), system provides helpful fallback message

### Technical Approach Decision

**Story 2.2 will use SQL-based Hybrid Search (NOT LangChain SupabaseVectorStore)**

**Rationale** [Source: docs/architecture/ai-orchestration-architecture.md#Hybrid-Search-Strategy]:

- Performance critical: User-facing recommendation feature requires <500ms warm response time
- Custom ranking logic: Weighted combination of vector similarity (0.7) + keyword match (0.3)
- Minimal abstraction: Direct SQL RPC provides full control and transparency
- LangChain optional: No need for retriever interface or RAG chain composition in this story

**LangChain Usage** [Source: docs/architecture/ai-orchestration-architecture.md#When-to-Use]:

- ⚠️ Optional for Story 2.2

### Hybrid Search Implementation Details

**PostgreSQL Function Specification:**

```sql
CREATE FUNCTION hybrid_search_books(
  query_embedding VECTOR(768),
  query_text TEXT,
  match_threshold FLOAT DEFAULT 0.7,
  limit_count INT DEFAULT 10
)
RETURNS TABLE (
  book_id UUID,
  title TEXT,
  author TEXT,
  ai_summary TEXT,
  similarity_score FLOAT,
  keyword_rank FLOAT,
  combined_score FLOAT
)
```

**Ranking Algorithm:**

- Vector similarity: `1 - (embedding <=> query_embedding)` (cosine distance)
- Keyword rank: `ts_rank(to_tsvector('english', title || ' ' || COALESCE(ai_summary, '') || ' ' || array_to_string(genres_primary, ' ') || ' ' || array_to_string(themes, ' ')), plainto_tsquery('english', query_text))`
- Combined score: `(similarity * 0.7 + keyword_rank * 0.3)`
- Filter: `status = 'to_read'`
- Threshold: `similarity > match_threshold`

**Why Weighted Combination:**

- Vector similarity captures semantic meaning (mood, tone, themes)
- Keyword matching captures explicit genre/topic requests
- 70/30 weighting prioritizes semantic understanding while honoring direct keyword matches

### Mood Input Examples

**Expected user inputs:**

- "I want something light and funny"
- "Give me a dark mystery with a strong female lead"
- "I'm in the mood for uplifting romance"
- "Something epic fantasy with complex world-building"
- "A thriller that will keep me on the edge of my seat"

**Processing flow:**

1. User sends `/recommend I want something light and funny`
2. System extracts mood text: "I want something light and funny"
3. Gemini Flash generates embedding vector from mood text
4. Hybrid search combines vector similarity + keyword matching
5. Returns top 3 books matching the mood criteria
