# Story 1.5.2: Data Ingestion & Book Matching

## Status

Ready for Review

## Story

**As a** ShelfHelp backend system,
**I want** to ingest historical Hardcover data and match existing Goodreads books to Hardcover book records,
**so that** I can establish a unified, deduplicated book database and enable accurate reading session tracking.

## Acceptance Criteria

1. Edge Function created at `supabase/functions/hardcover-sync/index.ts` with sync_type parameter ('full', 'activities', 'lists')
2. Book matching algorithm implemented with priority order: ISBN match → exact title+author → fuzzy match → manual review flag
3. Historical data ingestion: Query user's complete Activities history and backfill book_activities table
4. Idempotency guaranteed: Use hardcover_activity_id as deduplication key (unique constraint enforced)
5. Book mapping: For each activity, match or create book record with hardcover_id populated
6. Activity parsing: Extract and store activity_type ('added', 'started', 'finished', 'rated', 'progress_update', 'abandoned') from data JSONB
7. Reading session reconstruction: Parse activity deltas (page_progress changes) to calculate session_start, session_end, duration_minutes, pages_read, reading_speed_ppm
8. Manual review queue: Books with confidence <0.7 flagged in migration_log table for user confirmation
9. Migration logging: All matching decisions, confidence scores, and actions recorded in migration_log table
10. Dry-run mode: Sync function supports preview mode that logs actions without database writes
11. Progress reporting: Function returns summary (matched: N, unmatched: N, manual_review: N, activities_imported: N, sessions_created: N)
12. Integration tests cover: ISBN match, title+author match, fuzzy match fallback, session calculation, idempotency, error handling edge cases

```typescript
async function matchBook(goodreadsBook: GoodreadsBook): Promise<BookMatch | null> {
  // Priority 1: ISBN
  if (goodreadsBook.isbn) {
    const match = await matchByISBN(goodreadsBook.isbn);
    if (match) {
      await logMatch(goodreadsBook.id, match.id, "isbn", 1.0, "success");
      return { hardcover_id: match.id, confidence: 1.0, match_method: "isbn" };
    }
  }

  // Priority 2: Exact title + author
  const exactMatch = await matchByTitleAuthor(goodreadsBook.title, goodreadsBook.author);
  if (exactMatch) {
    await logMatch(goodreadsBook.id, exactMatch.id, "exact", 0.95, "success");
    return { hardcover_id: exactMatch.id, confidence: 0.95, match_method: "exact" };
  }

  // Priority 3: Fuzzy match
  const fuzzyMatches = await matchByFuzzy(goodreadsBook.title, goodreadsBook.author);
  if (fuzzyMatches[0]?.score >= 0.7) {
    await logMatch(goodreadsBook.id, fuzzyMatches[0].id, "fuzzy", fuzzyMatches[0].score, "success");
    return {
      hardcover_id: fuzzyMatches[0].id,
      confidence: fuzzyMatches[0].score,
      match_method: "fuzzy",
    };
  }

  // Priority 4: Manual review
  await createManualReviewLog(goodreadsBook, fuzzyMatches);
  return null;
}
```

```typescript
function parseActivityType(activity: HardcoverActivity): {
  activity_type: string;
  metadata: Record<string, any>;
} {
  const data = activity.data || {};

  if (data.rating) {
    return { activity_type: "rated", metadata: { rating_value: data.rating } };
  }

  if (data.page_progress !== undefined) {
    return {
      activity_type: "progress_update",
      metadata: { page_progress: data.page_progress },
    };
  }

  if (data.status_update) {
    const typeMap: Record<string, string> = {
      added: "added",
      reading: "started",
      finished: "finished",
      abandoned: "abandoned",
    };
    return {
      activity_type: typeMap[data.status_update] || "unknown",
      metadata: { status: data.status_update },
    };
  }

  throw new Error(`Unknown activity data structure: ${JSON.stringify(data)}`);
}
```

**Session Calculation Example:**

```typescript
function calculateSessions(activities: ActivityRecord[]): ReadingSession[] {
  const sessions: ReadingSession[] = [];

  for (let i = 1; i < activities.length; i++) {
    const prev = activities[i - 1];
    const curr = activities[i];

    const durationMs = curr.activity_date.getTime() - prev.activity_date.getTime();
    const durationMinutes = durationMs / 60000;
    const pagesRead = (curr.metadata.page_progress || 0) - (prev.metadata.page_progress || 0);

    // Validate session (max 4h, positive pages)
    if (durationMinutes > 0 && durationMinutes < 240 && pagesRead > 0) {
      sessions.push({
        book_id: curr.book_id,
        session_start: prev.activity_date,
        session_end: curr.activity_date,
        duration_minutes: Math.round(durationMinutes),
        pages_read: pagesRead,
        start_page: prev.metadata.page_progress,
        end_page: curr.metadata.page_progress,
        reading_speed_ppm: parseFloat((pagesRead / durationMinutes).toFixed(2)),
        data_source: "hardcover",
      });
    } else {
      // Log skipped session
      logger.warn({
        operation: "session_skipped",
        reason: durationMinutes > 240 ? "duration_too_long" : "invalid_pages",
        duration_minutes: durationMinutes,
        pages_read: pagesRead,
      });
    }
  }

  return sessions;
}
```

### Book Matching Strategy

**Priority Order (Highest to Lowest):**

1. **ISBN Match** (confidence: 1.0)

   - Direct lookup: `WHERE isbn_13 = $gr_isbn OR isbn_10 = $gr_isbn`
   - Most reliable, no false positives
   - Expected match rate: ~70% (most books have ISBN)

2. **Exact Title + Author** (confidence: 0.95)

   - Case-insensitive exact match: `LOWER(title) = LOWER($gr_title) AND LOWER(author) = LOWER($gr_author)`
   - Must normalize titles (strip series info, trim whitespace)
   - Expected match rate: ~20% (books without ISBN but clean metadata)

3. **Fuzzy Match** (confidence: calculated via pg_trgm similarity)

   - Use PostgreSQL's `similarity()` function with trigram matching
   - Require author exact match (ILIKE), fuzzy title match
   - Threshold: score >= 0.7 for automatic match
   - Expected match rate: ~5% (books with typos or variant titles)

4. **Manual Review** (confidence: <0.7)
   - Store top 5 fuzzy matches in migration_log
   - User must confirm or create new book
   - Expected rate: ~5% (obscure books, incomplete metadata)

**PostgreSQL Trigram Extension:**

```sql
-- Enable extension (if not already enabled)
CREATE EXTENSION IF NOT EXISTS pg_trgm;

-- Fuzzy match query
SELECT
  hardcover_id,
  title,
  similarity(title, 'The Great Gatsby') as score
FROM books
WHERE author ILIKE '%F. Scott Fitzgerald%'
ORDER BY score DESC
LIMIT 5;
```

**Confidence Score Interpretation:**

- 1.0: Perfect match (ISBN)
- 0.95: High confidence (exact title+author)
- 0.7-0.94: Medium confidence (fuzzy match, automatic)
- <0.7: Low confidence (manual review required)

### Reading Session Calculation

**Session Validation Rules:**

1. **Duration:** 0 < duration < 240 minutes (max 4-hour session)
   - Rationale: Realistic reading session length, filters out overnight gaps
2. **Pages:** pages_read > 0 (forward progress only)
   - Rationale: Ignore backward progress (re-reading, page corrections)
3. **Sequential:** Activities must be consecutive (ordered by activity_date ASC)

**Calculation Logic:**

```typescript
// Given activities: [A1, A2, A3] ordered by activity_date
// A1: page 50 @ 10:00 AM
// A2: page 75 @ 10:30 AM → Session 1: 30min, 25 pages, 0.83 ppm
// A3: page 100 @ 11:00 AM → Session 2: 30min, 25 pages, 0.83 ppm

const session = {
  session_start: A1.activity_date,
  session_end: A2.activity_date,
  duration_minutes: Math.round((A2.activity_date - A1.activity_date) / 60000),
  pages_read: A2.metadata.page_progress - A1.metadata.page_progress,
  start_page: A1.metadata.page_progress,
  end_page: A2.metadata.page_progress,
  reading_speed_ppm: parseFloat((pages_read / duration_minutes).toFixed(2)),
};
```

**Edge Cases:**

- **Skipped Pages:** If pages_read < 0 → skip session (user went backward)
- **Long Gaps:** If duration > 240 minutes → skip session (overnight or multi-day gap)
- **Single Activity:** No sessions created (need at least 2 activities for delta)
- **Duplicate Activities:** Use `hardcover_activity_id` unique constraint to prevent duplicates

### Error Taxonomy

All errors should follow this naming convention:

- `HARDCOVER_SYNC_ERROR`: Generic sync failure
- `BOOK_MATCH_FAILED`: Unable to match book (not manual review, actual error)
- `ACTIVITY_PARSE_ERROR`: Unable to parse activity data structure
- `SESSION_CALC_ERROR`: Session calculation failed (data integrity issue)
- `DATABASE_ERROR`: Supabase query/insert failure
- `MIGRATION_LOG_ERROR`: Unable to write to migration_log
- `NETWORK_ERROR`: Network failure during API call
- `VALIDATION_ERROR`: Input validation failure

**Error Handling Strategy:**

- Continue processing on individual book/activity failures
- Accumulate errors in `SyncResult.errors` array
- Log all errors: `operation=sync_error`, `error_type`, `message`, `context`
- Return partial success if some items processed successfully
