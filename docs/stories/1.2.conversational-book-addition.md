# Story 1.2: Conversational Book Addition

## Status

**Done**

## Story

**As a** Shelf Help Assistant user,
**I want** to add new books to my reading list using simple, natural language commands,
**so that** I can quickly build my library without needing to know exact titles or formats.

## Acceptance Criteria

1. User can add a book by providing title and author via natural language (e.g., "Add The Name of the Wind by Patrick Rothfuss")
2. Bot uses Gemini Flash to extract book title and author from natural language input
3. Bot searches Open Library API and Google Books API for book metadata (title, author, ISBN, page_count, cover_image_url), and attempts to scrape goodreads_id from Goodreads
4. Lookup tables (genres, subgenres, tropes, spice_levels, recommendation_sources) are populated from classifications.yaml
5. Book is saved to the database with status 'to_read' and current timestamp using parameterized queries
6. User receives confirmation message with book title, author, and cover image
7. If book cannot be found or ambiguous results exist, bot asks clarifying questions using inline keyboards
8. Bot provides friendly error messages for invalid inputs or failed searches, with proper input validation and rate limiting

### External API - Book Metadata and Goodreads Integration

**Note**: Goodreads officially deprecated their public API in December 2020. This story uses a multi-source strategy for comprehensive book metadata.

**Primary Sources (Both Required):**

**1. Open Library API**

- **Purpose**: Primary metadata source (title, author, ISBN, page count, cover images)
- **Cost**: Free, no API key required
- **Documentation**: https://openlibrary.org/developers/api
- **Search endpoint**: `https://openlibrary.org/search.json?title={title}&author={author}`
- **Rate Limiting**: No published limit, but be respectful - implement 1 request per second max
- **Response time**: Typically 200-500ms

**2. Google Books API**

- **Purpose**: Secondary metadata source and validation (additional metadata, publication details)
- **Cost**: Free with rate limits
- **Documentation**: https://developers.google.com/books/docs/v1/using
- **Search endpoint**: `https://www.googleapis.com/books/v1/volumes?q=intitle:{title}+inauthor:{author}`
- **Rate Limiting**: 1,000 requests per day per project (monitor and implement backoff)
- **Response time**: Typically 300-800ms

**3. Goodreads ID via Web Scraping**

- **Purpose**: Obtain goodreads_id for future RSS ingestion correlation (Story 1.4)
- **Method**: Web scraping Goodreads search results page
- **Search URL**: `https://www.goodreads.com/search?q={title}+{author}`
- **Rate Limiting**: Implement 2-3 second delays between requests, respect robots.txt
- **Fallback**: If scraping fails, allow NULL goodreads_id (can be populated later via RSS correlation)
- **Implementation**: Use Deno's native fetch with User-Agent header, parse HTML for book ID in URLs

**Integration Strategy:**

1. Query Open Library API first (fastest, most reliable)
2. Query Google Books API in parallel for additional metadata
3. Attempt Goodreads scraping last (optional, can fail gracefully)
4. Merge results, prioritizing Open Library for core fields
5. Store all source identifiers for future reference

**Rate Limiting Implementation:**

- Use a simple in-memory queue with delays between requests
- Open Library: 1 request/second
- Google Books: Track daily quota, implement exponential backoff on 429 errors
- Goodreads scraping: 2-3 second delays, max 20 requests/hour

### Input Sanitization and Security

**Database Security:**

- **SQL Injection Prevention**: Use Supabase client's parameterized queries exclusively - NEVER concatenate user input into SQL strings
- All user inputs passed as parameters to Supabase methods (e.g., `.insert()`, `.select()`, `.update()`)

**User Input Validation:**

- **Title/Author extraction**: Validate Gemini Flash output before using in API calls
- **Maximum lengths**: Enforce reasonable limits (title: 500 chars, author: 200 chars)
- **Character filtering**: Strip or escape special characters for web scraping URLs
- **JSONB state data**: Validate structure before storing in conversational_state table

**API Security:**

- **User-Agent headers**: Include appropriate User-Agent for Goodreads scraping to identify bot
- **API key protection**: GOOGLE_GEMINI_API_KEY never logged or exposed in error messages
- **Error message sanitization**: Don't expose internal system details in user-facing messages

**Example validation pattern:**

```typescript
function validateBookInput(title: string, author: string): { valid: boolean; error?: string } {
  if (!title || title.trim().length === 0) {
    return { valid: false, error: "Title is required" };
  }
  if (title.length > 500) {
    return { valid: false, error: "Title too long" };
  }
  if (author && author.length > 200) {
    return { valid: false, error: "Author name too long" };
  }
  return { valid: true };
}
```
