# Story 1.6: Core Error Handling & Logging

## Status

Ready for Review

## Story

**As a** solo developer,
**I want** centralized, standardized error handling and logging utilities across all Edge Functions,
**so that** debugging is easier, logs are consistent, and error responses follow a uniform format.

## Acceptance Criteria

1. A centralized logging utility exists at `supabase/functions/_shared/logger.ts` with structured JSON logging (requestId, timestamp, level, message, context)
2. A centralized error handling utility exists at `supabase/functions/_shared/error-handler.ts` with consistent error response formatting
3. All existing Edge Functions are refactored to use the centralized utilities (telegram-webhook, seed-lookup-data, csv-backfill, enrich-metadata, rss-ingestion)
4. Error responses across all functions follow a consistent JSON format with appropriate HTTP status codes
5. Logging includes proper log levels (info, warn, error, debug) and structured context
6. Unit tests validate logging utility formats output correctly
7. Unit tests validate error handler produces consistent responses
8. Documentation updated with logging and error handling standards for future development

### Data Models

**Logger Interface:**

```typescript
interface LogEntry {
  requestId: string;
  level: "info" | "warn" | "error" | "debug";
  message: string;
  timestamp: string; // ISO 8601 format
  context?: Record<string, unknown>;
}

interface Logger {
  info(message: string, context?: Record<string, unknown>): void;
  warn(message: string, context?: Record<string, unknown>): void;
  error(message: string, context?: Record<string, unknown>): void;
  debug(message: string, context?: Record<string, unknown>): void;
}
```

**Error Response Interface:**

```typescript
interface ErrorResponse {
  error: string;
  requestId: string;
  details?: unknown;
}
```

```typescript
function generateRequestId(): string {

function log(
  requestId: string,
  level: "info" | "error",
  message: string,
  context?: Record<string, unknown>,
): void {
  const logEntry = {
    requestId,
    level,
    message,
    timestamp: new Date().toISOString(),
    context: context || {},
  };

  if (level === "error") {
    console.error(JSON.stringify(logEntry));
  } else {
    console.log(JSON.stringify(logEntry));
  }
}
```

### Technical Constraints

[Source: docs/architecture/3-tech-stack-alignment.md, docs/architecture/12-lean-testing-strategy.md]

**Deno Constraints:**

- Must use Deno-compatible imports (jsr:, npm:, https://deno.land/x/)
- Edge Functions run on Deno runtime
- Use `crypto.randomUUID()` for UUID generation (Deno built-in)

**Testing Standards:**

- Use Deno Test Runner (`deno test -A`)
- Unit tests should NOT require external services (database, APIs)
- Focus on isolated logic testing
- Use mocks/stubs for console.log/console.error in logger tests

**Code Quality:**

- All code must pass `deno lint`
- All code must pass `deno fmt --check`
- TSDoc comments required for public functions
- Type safety enforced (no `any` types without justification)

**Error Response Standards:**

- HTTP 400: Bad Request (invalid input)
- HTTP 401: Unauthorized (missing/invalid auth)
- HTTP 403: Forbidden (valid auth, insufficient permissions)
- HTTP 404: Not Found (resource doesn't exist)
- HTTP 500: Internal Server Error (unexpected server errors)

**Logging Standards:**

- **info**: Normal operation events (request received, operation completed)
- **warn**: Recoverable issues (rate limit hit, fallback used)
- **error**: Failures requiring attention (API errors, database errors)
- **debug**: Detailed debugging info (only in development)

### Refactoring Strategy

**Step 1: Create Utilities**

- Build logger.ts with factory pattern: `createLogger(requestId)`
- Build error-handler.ts with helper functions for common HTTP errors

**Step 2: Test Utilities**

- Write unit tests for logger (validate JSON structure, levels)
- Write unit tests for error-handler (validate Response objects, status codes)

**Step 3: Refactor Functions (One at a Time)**

- Import utilities at top of file
- Replace local `generateRequestId()` and `log()` with centralized versions
- Replace manual error responses with error-handler helpers
- Test each function after refactoring

**Step 4: Cleanup**

- Remove all duplicated logging code
- Update documentation with new standards
