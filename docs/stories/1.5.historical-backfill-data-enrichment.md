# Story 1.5: Historical Backfill & Data Enrichment

## Status

Ready for Review

## Story

**As a** solo developer,
**I want** to import historical reading data from CSV, populate lookup tables from YAML files, and implement a metadata enrichment service,
**so that** the database contains all historical book data with complete classification metadata.

## Acceptance Criteria

1. Lookup tables (genres, subgenres, tropes, spice_levels, recommendation_sources) are populated from `classifications.yaml` and `recommendation-sources.yaml` files
2. Historical book data from `goodreads_read_history.csv` is imported into the `books` table
3. CSV import correctly maps Goodreads CSV columns to database schema fields
4. A metadata enrichment Edge Function can enrich book records with additional data (genres, tropes, themes, pacing, tone, etc.) using AI
5. The enrichment service integrates with the existing `books` table schema and updates classification fields
6. The enrichment process can be triggered manually or automatically for books missing metadata
7. Error handling ensures partial failures don't corrupt existing book data
8. Integration tests validate CSV import, YAML data loading, and book enrichment workflows
9. Documentation explains how to update YAML files, import CSV data, and trigger enrichment

### Data Models

[Source: docs/architecture/4-data-models-and-schema-changes.md]

**Lookup Tables Schema:**

```sql
CREATE TABLE genres (
    id SERIAL PRIMARY KEY,
    name TEXT UNIQUE NOT NULL
);

CREATE TABLE subgenres (
    id SERIAL PRIMARY KEY,
    genre_id INTEGER REFERENCES genres(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    UNIQUE (genre_id, name)
);

CREATE TABLE tropes (
    id SERIAL PRIMARY KEY,
    genre_id INTEGER REFERENCES genres(id) ON DELETE CASCADE,
    name TEXT NOT NULL,
    UNIQUE (genre_id, name)
);

CREATE TABLE spice_levels (
    id SERIAL PRIMARY KEY,
    label TEXT UNIQUE NOT NULL,
    description TEXT
);

CREATE TABLE recommendation_sources (
    id SERIAL PRIMARY KEY,
    name TEXT UNIQUE NOT NULL,
    url TEXT,
    scope TEXT,
    categories TEXT[],
    priority INTEGER
);
```

**`books` Table - CSV Import Fields:**

```sql
-- Core Identifiers
goodreads_id INTEGER UNIQUE,     -- from CSV "Book Id"
isbn TEXT,                        -- from CSV "ISBN13" (preferred) or "ISBN"

-- Bibliographic Data
title TEXT NOT NULL,              -- from CSV "Title" (series info extracted)
series_name TEXT,                 -- parsed from "Title (Series, #N)" pattern
series_number INTEGER,            -- parsed from "Title (Series, #N)" pattern
author TEXT NOT NULL,             -- from CSV "Author"
page_count INTEGER,               -- from CSV "Number of Pages"
publisher TEXT,                   -- from CSV "Publisher"
publication_date DATE,            -- from CSV "Year Published" → YYYY-01-01
goodreads_link TEXT,              -- constructed: https://www.goodreads.com/book/show/{goodreads_id}

-- User Data
user_rating INTEGER,              -- from CSV "My Rating" (1-5)
user_date_added TIMESTAMP,        -- from CSV "Date Added" (MM/DD/YY → ISO)
user_date_finished TIMESTAMP,     -- from CSV "Date Read" (MM/DD/YY → ISO)

-- Status
status TEXT DEFAULT 'to_read',   -- CSV: hardcoded to "finished" (only "read" books imported)
                                  -- Valid: 'to_read', 'currently_reading', 'finished', 'processing', 'enriched', 'failed'
```

**CSV Import Filtering**: Only books with `Status = "read"` are imported. Books with `to-read` or `currently-reading` are filtered out completely.

**`books` Table Enrichment Fields:**

```sql
-- Classification & Thematic Data (Enriched)
genres_primary TEXT[],
genres_secondary TEXT[],
tropes TEXT[],
themes TEXT[],
keywords TEXT[],
target_audience TEXT,

-- Stylistic & Structural Data (Enriched)
pacing TEXT,
tone TEXT,
writing_style TEXT,
pov_type TEXT,
pov_gender TEXT,
spice_level TEXT,
```

**CSV Data Source:**

- `project-specs/goodreads_read_history.csv`: Historical Goodreads reading data
- CSV Format: Header row with columns (Book Id, Title, Author, ISBN, ISBN13, My Rating, Average Rating, Publisher, Binding, Number of Pages, Year Published, Original Publication Year, Date Read, Date Added, Status)
- Date Format: MM/DD/YY (e.g., "9/20/25" = September 20, 2025)

**YAML Data Sources:**

- `project-specs/classifications.yaml`: Contains genres, subgenres, tropes, spice levels
- `project-specs/recommendation-sources.yaml`: Contains recommendation source data

**Data Loading Strategy:**

1. **Lookup Tables**: Parse YAML files → UPSERT into lookup tables (idempotent)
2. **Historical Books**: Parse CSV → Map columns → UPSERT into books table (match on goodreads_id)
3. **Enrichment**: Query books missing metadata → AI enrichment → UPDATE books table

### Technical Constraints

[Source: docs/architecture/3-tech-stack-alignment.md, docs/architecture/12-lean-testing-strategy.md]

**Deno Constraints:**

- Must use `npm:` prefix for npm packages (e.g., `npm:js-yaml`, `npm:papaparse`)
- Edge Functions run on Deno runtime
- File system access: Use `Deno.readTextFile()` to read local files from `project-specs/` directory
  - YAML files: `await Deno.readTextFile('./project-specs/classifications.yaml')`
  - CSV files: `await Deno.readTextFile('./project-specs/goodreads_read_history.csv')`

**Edge Function Authentication:**

- `seed-lookup-data`: Internal only (call manually via Supabase CLI for one-time setup)
- `csv-backfill`: Internal only (call manually for one-time historical import)
- `enrich-metadata`: Can be public or protected depending on use case (manual trigger for now)

**Database Constraints:**

- Foreign key relationships must be respected (genres before subgenres/tropes)
- UNIQUE constraints prevent duplicate entries
- Use transactions for atomic updates during enrichment:
  ```typescript
  // Transaction pattern for Supabase client
  const { data, error } = await supabase.rpc("begin");
  try {
    await supabase.from("books").update({/* fields */}).eq("id", bookId);
    await supabase.rpc("commit");
  } catch (err) {
    await supabase.rpc("rollback");
    throw err;
  }
  ```
- UPSERT on `goodreads_id` for CSV import (ON CONFLICT DO UPDATE)

**CSV Parsing Considerations:**

- Handle quoted fields (titles/authors may contain commas)
- Handle missing values (empty strings → NULL)
- Date parsing: MM/DD/YY format (e.g., "9/20/25" → 2025-09-20)
- ISBN preference: Use ISBN13 if available, fallback to ISBN

**AI Integration:**

- Gemini 1.5 Pro for complex metadata analysis
- API Key Security: Retrieve Gemini API key from Supabase Vault (use pattern from Story 1.4)
  ```typescript
  const { data: secrets } = await supabase.rpc("vault_get_secret", {
    secret_name: "GEMINI_API_KEY",
  });
  ```
- Prompt structure: Request JSON response with specific fields (genres_primary, genres_secondary, tropes, themes, pacing, tone, writing_style, pov_type, pov_gender, spice_level)
- Handle rate limits and API errors gracefully (retry logic with exponential backoff)
