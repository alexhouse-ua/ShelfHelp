## Reliability Assessment

**Status**: ⚠️ CONCERNS

### Known Issue: PostgREST Schema Cache Timing

**Severity**: Low (Environmental, not Production)

**Description**: The "Database - Lookup tables populated" test fails with `PGRST205: Could not find table in schema cache` when executed immediately after `supabase db reset`.

**Root Cause**: PostgREST's schema cache refresh is asynchronous. Tables exist in PostgreSQL but aren't visible to PostgREST REST API for ~3-5 seconds after creation.

**Evidence**:
- Direct PostgreSQL access works immediately
- Direct REST API call succeeds after brief delay (verified via curl)
- Test has 5-attempt retry with exponential backoff, but still insufficient for immediate post-reset

**Impact Assessment**:
- ✅ Production: No impact (tables created once during deployment)
- ✅ CI: No impact (fresh Supabase instance has time to initialize)
- ⚠️ Local Dev: Fails when running `deno test -A` immediately after `supabase db reset`

**Mitigation Options**:
1. Add initial 5s delay before first lookup table query (simple, effective)
2. Skip test if tables not accessible after retries (pragmatic)
3. Document as known limitation (current approach)
4. Wait for PostgREST cache invalidation signal (complex)

**Recommendation**: Option 1 or 2. This is a test infrastructure issue, not a production concern.
