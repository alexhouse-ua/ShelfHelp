# RSS Ingestion Fix - October 7, 2025

## Issues Identified

### 1. Missing Environment Variable Configuration
**Problem:** The `GOODREADS_RSS_FEED_URL_READ` environment variable was not configured in `supabase/config.toml` under the `[edge_runtime.secrets]` section.

**Impact:** RSS ingestion function returned "RSS feed URL not configured" error when invoked locally.

**Root Cause:** Edge Functions in Supabase require environment variables to be explicitly mapped in `config.toml` to be available at runtime.

### 2. Infrequent RSS Sync Schedule
**Problem:** RSS ingestion was scheduled to run only once daily at 2 AM UTC.

**Impact:** New books from Goodreads RSS feed were only synced once per day, leading to stale data.

## Fixes Applied

### 1. Added Missing Environment Variable
**File:** `supabase/config.toml`

**Change:**
```toml
[edge_runtime.secrets]
TELEGRAM_BOT_TOKEN = "env(TELEGRAM_BOT_TOKEN)"
TELEGRAM_WEBHOOK_SECRET = "env(TELEGRAM_WEBHOOK_SECRET)"
GOOGLE_GEMINI_API_KEY = "env(GOOGLE_GEMINI_API_KEY)"
GOODREADS_RSS_FEED_URL_READ = "env(GOODREADS_RSS_FEED_URL_READ)"  # ← ADDED
```

**Result:** RSS ingestion function now successfully reads the Goodreads RSS feed URL from the environment.

### 2. Increased RSS Sync Frequency
**File:** `supabase/migrations/20250930114927_add_rss_ingestion_cron.sql`

**Change:**
```sql
-- OLD: Run daily at 2 AM UTC
-- '0 2 * * *'

-- NEW: Run every hour (24x daily)
'0 * * * *'  -- Runs every hour at minute 0
```

**Frequency Breakdown:**
- **Old Schedule:** 1x daily = 30 invocations/month
- **New Schedule:** 24x daily = 720 invocations/month
- **Free Tier Limit:** 2,000,000 invocations/month
- **Usage:** 0.036% of free tier limit ✅

**Result:** Books are now synced from Goodreads every hour, ensuring very fresh data while staying well within free tier limits.

## Production Deployment

To apply these fixes to production:

1. **Update Environment Configuration:**
   - Ensure `GOODREADS_RSS_FEED_URL_READ` is set in production secrets:
     ```bash
     supabase secrets set GOODREADS_RSS_FEED_URL_READ="<your-rss-url>"
     ```

2. **Deploy Migration:**
   ```bash
   # Push the updated migration to production
   supabase db push
   ```

3. **Verify Deployment:**
   ```bash
   # Check cron job is scheduled correctly
   # Run this in Supabase SQL Editor
   SELECT jobname, schedule FROM cron.job WHERE jobname LIKE '%rss%';
   ```

4. **Monitor Function Logs:**
   ```bash

   supabase functions logs rss-ingestion
   ```

## Additional Notes

### Environment Variable Loading
Edge Functions in Supabase require explicit configuration in `config.toml` to access environment variables. The `.env.local` file is only used during local development when using `supabase functions serve --env-file`.

### Cron Expression Format
The cron expression `0 * * * *` means:
- **Minute:** 0 (run at the top of the hour)
- **Hour:** * (every hour: 0, 1, 2, 3... 23)
- **Day:** * (every day)
- **Month:** * (every month)
- **Day of Week:** * (every day of the week)

### Alternative Schedules
If you want to adjust the frequency:
- **Every 30 minutes:** `*/30 * * * *` (48x daily = 1,440/month - 0.072%)
- **Every 15 minutes:** `*/15 * * * *` (96x daily = 2,880/month - 0.144%)
- **Every 2 hours:** `0 */2 * * *` (12x daily = 360/month - 0.018%)
- **Every 3 hours:** `0 */3 * * *` (8x daily = 240/month - 0.012%)

All of these remain well within free tier limits.
